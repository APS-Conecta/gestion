# 0009 — The establishment is instance configuration, never a constant

Accepted, 2026-08-02.

## Context

This decision binds every app, and its body is almost entirely about files in this repository, which is why it
lives here ([ADR-0007](0007-org-wide-decisions-live-in-this-repository.md)). It is the authority for *"which
establishment an install serves is instance configuration"*.

## Decision

Every app must be **CESFAM-agnostic**: no DEIS code, clinic name or comuna in code, fixtures or queries. This
repository carries the identity in `sites/<slug>/site.sh` (`SITE_DEIS`, `SITE_NOMBRE_CORTO`, `SITE_COMUNA`,
`SITE_SERVICIO_SALUD`), generated by `scripts/deis.py` and sourced by `seed.sh`.

When a consumer needs the establishment, the seam is **propagation**: a provisioning phase writes it to an app
config key, and the app reads that key. Phase 16 is the only writer of Estadística's `deis_code`,
`establishment_type` and `comuna_cut` (the app has no setter), behind a guard that stops the install on anything
but a six-digit code; Territorio's `comuna_cut` and `comuna_name` are the other seam.

**One establishment per instance**: another clinic is another `sites/<slug>/site.sh` and another deployment,
not a picker.

**Comparison, never a selector.** The configured establishment's figures stand beside the country's and a peer
group's (the establishments sharing the traits the viewer picks), aggregates over every establishment that
reported to DEIS; no page lets anyone make another clinic «ours». Living docs and dated history do not name the
establishment; the register CSV and git history are exempt.

## Consequences

- Agnosticism costs nothing at the data layer: the DEIS extracts are national, and which clinic we show is a
  **filter value**, not a pipeline.
- Any REM read API takes the DEIS code as a **parameter**, not an implicit "ours", so a selector stays
  additive.
- A shape-based runnable check holds agnosticism: no tracked file may hand `deis.py` a DEIS code (the gate
  lives in `scripts/test.sh`). It must keep returning nothing in code, fixtures and tests included, or
  agnosticism is untested.
