# Organisation map

Which repository owns what, for a person or an agent meeting APS-Conecta for the first time. Read it once and you should be able to answer *"where does this fact live?"* without opening every repository.

This file restates nothing that has an owner; it links instead. One owner per fact — others link, they do not repeat. Where this file and an owner disagree, the owner is right. Verified 2026-09-10.

## The generated half

The inventory — which repositories exist, which are cloned here, which are missing, and which sit inside another — comes from `repo-docs discover`. It is not written in this file and must not be.

`discover` reads each clone's identity from its git remote, not from the directory it happens to sit in. A directory can be renamed, copied or left behind; a remote cannot be renamed by accident. So a nested clone with its own remote is reported as its own repository, and a directory named after a repository that has no remote is reported as what it actually is.

The table below names repositories in order to attribute ownership. It is not the inventory, and it carries no count. If the two ever disagree, `discover` is right.

Three corrections the table depends on, because each is widely assumed and each is false:

- **`gestion` is not the home of every org-wide fact.** [ADR-0011](adr/0011-org-wide-facts-live-in-gestion.md) decides that an org-wide *decision* lives in `gestion/docs/adr/`. [ADR-0012](adr/0012-only-the-generic-half-is-published-as-an-org-default.md) sends the generic half of the shared documents — contributing, security, issue and pull-request templates — to `.github` to be published from there. `repo-docs` owns the documentation conventions and the canon of mechanical artifacts every repository inherits. The brand source (tokens, logo artwork, the living brandbook) is a separate kit outside git, with the Site's copies in `aps-conecta-web`: see [BRANDING.md](BRANDING.md), [THEMING-MODEL.md](THEMING-MODEL.md) and [LICENSING.md](LICENSING.md).
- **`aps-conecta-web` is not "the home of the brand shared by every product".** Its ADR-0006 superseded ADR-0001 on 2026-08-05: there is no single shared brand package, the identity exists as per-product variants, `gestion` maintains its own for Nextcloud product chrome, and neither is upstream of the other. Its `CONTEXT.md` still carries the superseded premise. Nor is that repository the authority for what the live Site says and serves: its ADR-0022 (2026-09-06) retired the gates that observed the running Site, so its remaining checks answer only *"does the repository still describe what is installed?"*.
- **`repo-docs` owns the mechanism, not the policy.** The documentation rules are `gestion`'s and `repo-docs` links to them rather than restating them; org-wide decisions are `gestion` ADRs; most of its `canon/` is harvested from `gestion`, which its own profile names as the organisation's exemplar. `.github`, likewise, distributes rather than decides, and inheritance there is partial by design: an issue-template folder is all-or-nothing, and code owners, workflows and git hooks cannot be inherited at all.

`Databases` ships no CI; its gates are local. The one gate that can go red is red as of 2026-09-10 — the catalogue's last probe is older than the maximum age the catalogue itself allows. Ageing is the failure by design, and nobody has re-run the probe. Its REM directory ships no README, no schema and no generator: versioned, but undocumented.

## Why two repositories live inside another

`epidemiologia` and `territorio` are cloned into this repository's `apps/` directory, which `gestion` gitignores and bind-mounts into the container's custom apps directory. An edit inside either clone is live in the running development instance without a rebuild — that is the whole reason for the arrangement.

They are **not submodules**. There is no `.gitmodules` and nothing here pins a commit of either app. That is also why the inventory is generated from remotes: on disk they look like directories of `gestion`, and only the remote says otherwise.

An install never uses those clones. `epidemiologia` ships to a clinic as a vendored tarball under `provisioning/apps/`, verified by checksum with its provenance recorded beside it; `territorio` is a lab app and ships to nobody yet. [`../apps/README.md`](../apps/README.md) explains the directory, and [`../CONTEXT.md`](../CONTEXT.md) defines shipped, vendored, own and lab apps — the words that make the distinction sayable.

## Decisions that were reversed

An accepted ADR is not automatically current. Read the Status line, then any dated correction at the foot of the file, before acting on the body. Numbers are never reused and never renumbered; a decision that moves leaves a stub at its old address.

**In this repository.** [ADR-0010](adr/0010-agpl-across-the-org.md) supersedes [ADR-0007](adr/0007-proprietary-across-the-org.md) (2026-08-07): the proprietary posture was never available, because the Nextcloud apps link AGPL code; the identity is protected by trademark instead. [ADR-0001](adr/0001-server-theme-for-branding.md) supersedes AD-6 inside [ADR-0000](adr/0000-inherited-decisions.md) — config-only white-labelling cannot serve brand typography. [ADR-0003](adr/0003-this-stack-ships-a-custom-app.md) *reverses* AD-1 rather than narrowing it: this stack does ship an app of its own. [ADR-0004](adr/0004-branding-the-legacy-render-path.md) amends [ADR-0001](adr/0001-server-theme-for-branding.md) and brings back the theme's `defaults.php`, because legacy-rendered screens bypass the theming service. [ADR-0002](adr/0002-app-patches.md) records two partial reversals of AD-5. Two stale traps survive this: ADR-0000's AD-6 entry still concludes that `defaults.php` was rightly deleted and carries no note of ADR-0004, and [`../ROADMAP.md`](../ROADMAP.md) still lists it as unnecessary — the file is tracked, load-bearing, and the smoke gate fails without it. The compose file's "AD-1" comments cite a decision that no longer exists.

The numbering here has permanent gaps at 0006, 0008 and 0009: ADR-0007 and ADR-0010 arrived from `aps-conecta-web` on 2026-08-08 keeping their numbers, and [ADR-0013](adr/0013-the-establishment-is-instance-configuration.md) arrived from `epidemiologia` on 2026-08-09 under a new number because 0003 was already taken.

Cite any of them by repository name and absolute URL; a relative path to a sibling clone passes locally and fails in CI.

## What has no owner

Everything below sits outside every repository: unversioned, unbacked, and belonging to nobody. Two repositories were created since these were catalogued — `Databases` and `calculadora-ecicep` — and each is commonly assumed to have absorbed one of these piles. Neither did.

- **An identified patient registry.** A risk-stratification workbook holding national IDs, names, home addresses, telephone numbers and email addresses joined to diagnoses, for tens of thousands of people, unencrypted, with no access control, no retention rule and no owner. Nothing scopes or ignores it, so any future `git init` at that root, any backup sync or any folder share publishes it. It is governed by the very statutes `Databases` now versions as corpus — the organisation versions the law and leaves the breach loose beside it. **Not superseded, and must never be:** the correct end state is deletion or a controlled encrypted store, not version control.
- **Its "randomised" sibling.** The direct national identifier survives in it, so it is personal health data, not an anonymised extract; nothing records who produced it, what was dropped, or whether it may be shared. Because the filename reads as safe, it is the copy most likely to be sent somewhere. **Not superseded.**
- **The DIPRECE/MINSAL AUGE-GES corpus and its crawler.** Roughly 3.5 GB of pathology documents, index caches and populated REM series extracts, produced by a hand-tuned multi-phase crawler that exists in exactly one copy. **Not superseded by `Databases`:** the filename intersection is two unrelated files and the only shared content is a single law PDF. The repository ships blank series spreadsheets at newer revisions; the loose tree holds the data dictionaries at older ones and the populated extracts, which the repository does not have at all. The source site has already lost links the crawler carries a recovery phase to repair, so a re-run today would not reproduce it: lose the directory and the corpus is gone.
- **A staff registry derived from public transparency documents.** Named staff joined to grade, contract type and post, with the parsers that build it. The sources are public; this machine-readable join is not, and nothing records that provenance, so nobody can say whether it may be republished. It describes a primary-care establishment of this organisation. **Not superseded.**
- **Provisioning scratch from a 2026-07-24 acceptance run.** A directory whose own notes say to delete it when it stopped being useful, still holding credential *values* — a verbatim copy of this repository's environment file, and a container-manager credential whose scope is every container on the host, not just this stack. Most of those values still match the running stack. The `.gitignore` entry that protects the real environment file does not reach a copy outside the repository, so the one control the organisation relies on here is bypassed by a folder that was meant to be gone. **Not superseded. Rotate, then delete.**
- **Vendored upstream clones of third-party libraries.** Recoverable — every clone has a live upstream — but hundreds of megabytes of nested repositories that no manifest lists, so nobody can say which pins informed which decision, and naive tooling drowns in them. Should be a list of repositories and commits, not working trees.
- **A git bundle of this repository from 2026-08-04.** Every commit in it is already present here and pushed. It protects nothing, is weeks behind the current head, and its filename asserts a guarantee nothing verifies — which is worse than no backup, because it invites someone to trust it.
- **A cross-repository architecture audit and improvement plan (2026-08-12).** The highest-value-per-byte document in the tree, in one copy, in no repository, with its implementation phase unwritten. Its value is entirely in the future — the conclusions could only be re-derived at full cost. It is already drifting: it lists as unversioned a directory that has since moved into `Databases`, and it still counts a retired library as in-scope. It needs a repository.
- **The specification and plan for `epidemiologia`.** The app's written spec lives outside the repository that implements it, so the two can diverge with nothing able to detect it. Beside it: an orphaned dependency tree for an app whose source no longer exists anywhere, and several empty name-only directories that make the roadmap look further along than it is. **Not superseded.**
- **The ECICEP source spreadsheet.** This is the sharpest supersession trap, and the answer is no. `calculadora-ecicep` versions the *derived* artifacts and its own ADR-0001 declares the spreadsheet — not the ministerial PDFs — to be the specification, with the spreadsheet winning any disagreement; its tests pin per-condition counts to a tab of that sheet read on a stated date. The sheet itself is tracked by nothing. The engine's row order is load-bearing, so if the sheet is lost nobody can ever again confirm that the shipped ordering matches it, or regenerate it after a source update — and the tests would stay green, because they check the port against itself.
- **The brand and design sources.** The WordPress design package exists as two byte-identical unversioned copies plus an older, incomplete zip; the Nextcloud brand kit is a fourth copy of the same identity; and the only copy of the script that applies the theme to a running instance is inside an archived zip. Per `aps-conecta-web` ADR-0006 the identity is legitimately a family of per-product variants — but the upstream those variants are copied from is versioned nowhere, and a token edit reaches production only if a person retypes it. One of those folders also holds the sole record of a licence withdrawal, preserved as a `.bak` that can be deleted without trace.
- **The project pitch deck.** Forty-odd slides of strategy in one copy, whose README points at a brand directory that does not exist and names an exported file that is not there. The artifact used to recruit people to the project is unversioned and already broken.

The fix for every item above is the same shape: give it an owner, or delete it. Nothing here is waiting on a decision that has not been made — it is waiting on someone doing one or the other.
