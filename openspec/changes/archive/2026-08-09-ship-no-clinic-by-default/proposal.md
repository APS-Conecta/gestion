## Why

`README.md` line 5 promises the product "names none" of the establishments it serves, and `AGENTS.md`
makes it an invariant: one establishment per install, *"named in that install's configuration and
never in the product"*. The repo breaks its own promise. A clone ships **CESFAM Los Castaños** — a
real, operating establishment (DEIS 114302, La Florida) — as the default a new operator is told to
run, in `sites/los-castanos/site.sh`, in three places in the README, in two CLI hints, and baked
into the theme at rest as `--aps-clinic: "CESFAM Los Castaños"`.

Los Castaños is our **pilot**: the real site where the suite gets its production trial. That is
exactly why it cannot be what a clone contains. Whoever clones or installs from a tag must arrive at
an empty stack and choose their own establishment from the DEIS register we ship — and the register
covers nine kinds of primary-care establishment, not only CESFAM, which the prose does not say.

## What Changes

- **No establishment ships as a default.** `sites/los-castanos/` leaves git. `make install` on a
  fresh clone stops at "choose your establishment" — the behaviour `require_site()` already
  implements, now the only path rather than the one you take if you decline the default.
- **A site file is per-install configuration, like `.env`.** `sites/<slug>/` becomes gitignored as a
  rule, not as a special case for one establishment. The DEIS register CSV stays tracked — it is
  what you pick *from*. This is what makes the guarantee hold for the next real clinic too, instead
  of re-deciding it each time.
- **The theme's per-install CSS stops being tracked.** `themes/apsconecta/core/css/site.css` is
  generated by `15-branding.sh` on every install and carries exactly one thing — the establishment's
  name. It is the same class of artifact as a site file, so it takes the same rule: gitignored,
  written on the install host. A checkout that has never been provisioned has no such file, and
  `server.css`'s declared `var(--aps-clinic, "APS Conecta Gestión")` fallback renders the product
  name. The repo is agnostic by code path, not by a committed string somebody must keep neutral.
- **The vocabulary stops saying CESFAM where it means any APS establishment.** `scripts/deis.py`
  already keeps CESFAM, PSR, CECOSF, CGR, CGU, COSAM, SAPU, SAR and SUR, and its search already
  accepts any of them — `deis.py sapu florida` works today. The docs, prompts and hints say "CESFAM"
  and "clinic" throughout, which misreports what the tool does.
- **Los Castaños survives as local, untracked pilot configuration.** Nothing about the live suite
  stops working; its site file simply stops being something a clone receives.
- **BREAKING for existing working copies.** After this lands, `git pull` deletes
  `sites/los-castanos/site.sh` from any working tree that has it. Anyone running `SITE=los-castanos`
  must keep a copy before pulling. One developer today, so the cost is a preserved file — but it is
  silent data loss if unannounced, so it is called out in `CHANGELOG.md` and in the tasks.

## Impact

- **Removed from git:** `sites/los-castanos/site.sh` and `themes/apsconecta/core/css/site.css` — both
  per-install artifacts, both kept locally and regenerated by provisioning.
- **Code:** `.gitignore` (ignore `sites/*/` and the generated `site.css`, keep the register);
  `scripts/env.sh` (`require_site()` hints); `scripts/env-init.sh` (post-`make setup` next step);
  `scripts/test.sh` (the ADR-0001 asset guard must distinguish its one generated path from six static
  ones); `provisioning/phases/15-branding.sh` (its comment describes a committed copy that is gone);
  `scripts/deis.py` (docstring, prompts and the generated site-file comments).
- **Docs:** `README.md` (quickstart step 3, step 4's sample output, the `sites/` row in *Where things
  live*), `provisioning/README.md` § *The clinic's own data*, `docs/ARCHITECTURE.md` and
  `docs/CONVENTIONS.md` (CESFAM used where any establishment is meant), `CHANGELOG.md`.
- **Not touched:** `docs/adr/0005-*.md` cites `sites/los-castanos/site.sh` as evidence that was true
  when the decision was taken. An ADR records a decision at a date; it is not rewritten because the
  repo moved on.
- **Already correct, verified, no work:** the GitHub *About* description ("One establishment per
  install"), the `APS-Conecta` org description, the org profile README, and all seven sibling repos —
  a code search returns zero hits for the name in each.
- **Already correct:** `.github/workflows/cleanboot.yml` writes its own `sites/ci/site.sh` with
  `deis.py --new`, so CI never depended on the shipped establishment and needs no change. It is also
  the standing proof that the from-nothing path works.
- **Risk:** the gate touches this change twice and must be confirmed rather than reasoned about — it
  lints `sites/*/site.sh` (a glob that will match nothing on a bare clone) and it asserts every
  `/themes/apsconecta…` path in `server.css` exists on disk, which today includes the `@import`ed
  `site.css`. See `design.md` § *Risks*.
